# Action-horizon (A) annotated rollouts — failure analysis

Generated by `planner_poc/play_annotated_horizon.py` with `runs/stage2_2b_btn/plan_stage1_600.pt`
(the combined direction+button steering model), cfg=8, H=18, **System-2 plan GENERATED fresh each
re-infer cycle** (game-agnostic planner prompt). For each game we ran **A=2** and **A=4** — the
execution/action horizon = how many of the 18 predicted rows are executed open-loop before the agent
re-observes and re-plans. Each `play.mp4` shows a frame after EVERY executed action with the action
(stick + buttons) and the plan that drove it drawn on the frame; `actions.txt` is the per-action log.

Games: STK (racing), Trigger Rally (racing), TheXTech (2D platformer — out of NitroGen's racing-heavy
comfort zone).

## Failure taxonomy (what to look for in the videos)

**A. System-1 / System-2 misalignment (the headline failure).**
The System-2 planner repeatedly emits a correct-looking directive (STK: "Steer left to follow the
track" almost every cycle) but System-1 (the frozen DiT) ignores it and steers the other way. STK A=2
re-plan#05 plan="Accelerate…" → stick **+1.04 (hard RIGHT)**; Trigger A=4 re-plan#02-04 plan="Steer
left…" → stick stays **+0.5–0.6 (right/neutral)**. This is the left/right grounding gap: the frame
prior dominates the plan token. (Up/forward and buttons are followed far more reliably than L/R.)

**B. A=4 amplifies commitment to a wrong/stale action.**
Because A=4 executes 4 rows open-loop before re-planning, a wrong action is held ~2× longer than A=2
and the error compounds within the chunk: STK A=4 re-plan#01 ramps **+0.55 → +0.98 → +0.97 → +0.96**
(accelerating RIGHT) while the plan says "steer left"; Trigger A=4 re-plan#01 holds **y≈+1.2 (brake)**
for all 4 rows under an "accelerate" plan. A=2 gets to re-observe and correct twice as often, so it
drifts off-line less. This is the core action-chunking trade made visible.

**C. Button mashing on out-of-distribution games (platformer).**
On TheXTech the DiT has a weak prior, so it emits diffuse, high-pressure actions: A=4 re-plan#01
presses **A/jump,B,Y,RT,RB,Dl,Dr simultaneously** (7 buttons at once). Racing games stay cleaner but
still show spurious presses (X/shoot, B, Y, and occasionally **Start** → pause-menu risk).

**D. Menu-stranding on TheXTech (verified by ground-truth state — NOT a death).**
TheXTech is open source, so we instrumented it to export player state each frame
(`docs/env_candidates/thextech_state_export.patch`). The state tracking **corrected an earlier
pixel-only misread**: across runs the hero **never dies** — `lives=3, dead=0` the whole time. What
actually happens: the agent either spuriously presses **Start** (which the env maps to Enter = pause)
or **runs off the right edge** of the short test level (x→800), which opens TheXTech's test-pause menu
("Restart Level / Quit Testing"). Position then freezes (paused) and the agent is **stranded** — it has
no menu-navigation capability, so it flails (saturated sticks, random buttons) and the VLM, correctly
reading the menu, emits "Press Restart Level" but can't operate it. Masking the menu button keeps the
agent in gameplay (it then crosses the lava to the right platforms, still `lives=3`). Lesson: the
"failure" here is harness/menu-stranding + the action policy having no menu affordance — not a game
death. Ground-truth state is what made this distinguishable from pixels.

**E. Stick saturation.**
Raw stick output is unbounded; under strong priors it exceeds [0,1] (TheXTech stick **+1.48**; STK
**+1.05**). The env clamps at 0.5±thresh so control still resolves, but it shows the policy pushing a
direction "as hard as it can" rather than modulating.

## Takeaways
- L/R is the dominant failure axis (consistent with the env-free probes); buttons/forward are followed.
- A is a real reactivity knob: **smaller A recovers faster from System-1/System-2 disagreement**; larger
  A is only safe where the per-chunk prediction stays on-policy (markovian racing on-track segments).
- The platformer exposes both System-1 (button mashing) and System-2 (menu hallucination) weaknesses —
  the System-2-heavy regime where this whole plan-conditioning effort is headed, and where env reward
  (not just env-free override) will be needed.
