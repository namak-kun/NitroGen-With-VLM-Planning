# GPT-5.5 Round 4 — RED-TEAM: the plan may be load-bearing after all

## 1. Steelman: on-manifold zero-gradient does not imply off-manifold zero-gradient

The R3 consensus rests too heavily on a domain transfer that has not been measured. The fact that the frozen base DiT reproduces expert-demo actions from frame alone is strong evidence only on the expert visitation distribution. But the drift problem is, by definition, the induced distribution after the policy has made mistakes. DAgger's point is exactly that these distributions differ (Ross, Gordon, Bagnell, arXiv:1011.0686): a behavior-cloned policy's own states are not the expert's states. Therefore “plan gradient ≈ 0 on demos” is not a theorem about drift states; it is a measurement on the wrong distribution.

Off-trajectory frames are also more likely to be semantically ambiguous. A trained-game expert frame may encode “move right now” because position, velocity, sprite pose, camera, and level phase correlate tightly with the streamer action. A drifted frame may be a weird subpixel alignment, stalled sprite, wrong enemy phase, edge-of-platform recovery, or post-damage state. In those states the frame-only actor may have no reliable local prior, while the plan supplies the missing semantic direction: “recover to the route,” “go right but jump over the pit,” “return to the platform.” The plan can re-acquire authority exactly where the frame prior is weak.

The measurement that exposes this is not R_B − R_A on normal evaluation alone. We need an off-policy/off-trajectory plan-gradient map. Collect gate-triggered or perturbation-generated states, then for each state compute: (a) action/velocity delta `G = mean_i ||v_c - v_u|| / (||v_u||+eps)` inside `eval_policy._sample_chunk` where CFG already computes `v_c` and `v_u`; (b) behavioral delta between correct-plan, wrong-plan, and null chunks; (c) downstream short-horizon recovery reward from the same save-state. Stratify by on-demo, mild drift, severe drift. If `G` is near zero on demos but rises on drift states and predicts recovery under the correct plan, R3's “plan not load-bearing” claim fails in the only regime that matters.

## 2. Attack on the 3-rung discriminator: it can miss plan × actor interaction

The running ladder is useful but structurally assumes additivity: R_A=live/no-adapt, R_B=oracle/no-adapt, R_C=oracle/actor-adapt. It can miss the case where an oracle plan is only useful after the actor has learned to obey plan-conditioned recovery maneuvers. A frozen off-manifold actor may ignore a perfect plan because the PlanAdapter/DiT routing never trained on that state; after LoRA adaptation, the same plan may become actionable. Then `R_B - R_A` underestimates the plan, and `R_C - R_B` misattributes a joint plan+actor improvement to “pure actor.”

It can also miss freshness. In `rwbc_actor_adapt.py`, `fixed_plan` is a single correct string, while live plans are regenerated only by cadence in collect/eval. In `eval_policy.act`, replanning is cadence-based (`replan_every`), not explicitly tied to a drift gate. A fixed oracle sentence is not the same as “full-depth frozen VLM rereads the drifted frame and emits the right recovery objective now.” If the relevant plan signal is state-contingent recovery text, R_C hides it.

Add the fourth rung:

- **R_D = oracle-plan + actor-adapt + replan-AT-drift.** Use the same actor delta as R_C. During eval, when the agreed gate fires (`D_t > τ_D`, high `r_t`, or `r_t≈0` plus no progress), regenerate the plan from the current drifted frame/history with the oracle task instruction, then continue. Keep seeds/save-states paired with R_C.

Exact metric: `Δ_interaction = mean_seed(Return_D - Return_C)` on identical starts, plus a gate-local metric `Δ_recovery = mean_trigger(PostNReward_D - PostNReward_C)` over the first N chunks after the first gate fire. Also report `escape_rate`: fraction of gate-triggered states with positive progress/no death within N chunks. If `Δ_interaction` is small but `Δ_recovery` is large, the plan is load-bearing locally even if episode return is noisy.

## 3. Entanglement: stale plans can cause actor-OOD, making the split false

R3 treats actor-OOD and plan-OOD as separable. But a stale/wrong objective can be the cause of the off-manifold state. If the VLM says “go right” while the current situation requires “wait/jump/turn back,” the actor follows a locally plausible but semantically wrong command, leaves the demo route, then becomes actor-OOD. In that causal chain, fixing plan staleness indirectly reduces actor-OOD. Saying “the cure is actor data” is incomplete: better staleness-offset training and replan-on-drift can prevent the actor from visiting the bad states in the first place.

Separating causation from correlation requires an intervention. From known-good emulator save-states, run paired rollouts with the same actor and RNG under: correct plan, null plan, deliberately wrong/stale plan (opposite direction, previous-room objective, or delayed plan from t−K), and fresh replan-on-drift. Measure time-to-drift: first gate trigger, first no-progress window, route deviation from a reference, damage/death, and return. If wrong/stale plans significantly shorten time-to-drift versus correct/null, plan error is a causal source of actor-OOD. Then test staleness-offset training: train on `(frame_t, plan_{t-K}) -> recovery/correction` and ask whether it delays drift onset without any additional actor LoRA.

## 4. Failure modes of the proposed cure

Reward-ranked self-imitation and save-state GRPO can self-deceive. GRPO-style relative ranking (DeepSeekMath/GRPO, arXiv:2402.03300) optimizes whatever scalar the environment exposes; AWR (Peng et al., arXiv:1910.00177) similarly weights actions by advantage estimates. If the reward is wrong, the learned policy becomes wrong faster. The recently fixed expert-denominator bug is a warning: metrics can look normalized and scientific while selecting nonsense. A survival-sprint that exploits `screen_x`, camera scroll, or “do not die” can outrank real task completion; a policy can camp, oscillate, farm reward, trigger emulator quirks, or overfit save-state resets. Save-state GRPO is especially vulnerable to branch-search distributional collapse: repeatedly selecting top short-horizon chunks teaches the model the reward proxy's blind spots, not the game.

Mandatory guardrails: multi-component rewards with hard task checks, not only `screen_x`; paired human/scripted baselines and fixed expert denominators; held-out save-states and held-out games; logging video for top-ranked rollouts; adversarial reward audits with wrong-plan/null-plan controls; KL/anchor to the base actor plus action-entropy floors; per-game reward normalization before mixing into one generalist; cap repeated use of the same save-state; test on sparse terminal objectives, not just dense progress; and maintain exact null-invariance (`masked` null path in `nitrogen/planner.py`) as a regression test so adaptation does not corrupt the base no-plan behavior.

## 5. Concession criteria

I concede R3 if the expanded discriminator shows all of the following on paired SMW/Sonic save-states: `R_B - R_A <= +0.05` native normalized return; `R_C - R_B >= +0.10`; `R_D - R_C <= +0.03`; gate-local `PostNReward_D - PostNReward_C <= +0.03`; and off-trajectory plan-gradient `G` remains demo-like (no significant rise, and correct-vs-wrong plan chunks do not change recovery reward). That would show the plan neither helps standalone nor in interaction nor at drift moments. Anything else means the consensus is incomplete: actor adaptation is necessary, but plan freshness/authority may still be load-bearing.
