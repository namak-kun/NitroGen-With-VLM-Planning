## 1. INFRA CATCHES & PROBLEMS (excruciating detail)

### 1.1 RAM progress signals are unreliable — in BOTH directions
- **Magnitude is not cross-level comparable.** SMW `screen_x` scales differently underground / after a
  pipe-warp, so a big `screen_x` number can be a level-geometry artifact, not "further." Do NOT quote raw
  `screen_x` magnitudes across different start states.
- **RAM misses some deaths.** The `survival_advance` death heuristic (lives-decrement 1–3, or progress reset
  > 40 px) does not catch every death state (e.g. a fade/again-screen that doesn't decrement lives in the window).
- **SMW 'score' RAM does NOT register kills** (verified on a human's own spin-jump-kill → score stayed flat).
  To detect a kill you need sprite-status RAM, not score. (Blocks the Rex/spin-jump-kill outcome eval.)
- **SMB1 All-Stars world-x = `0x7E0042`** (`<u2`), found by correlating WRAM bytes vs measured frame-scroll
  (online maps `0x6D/0x86/0xD4` were WRONG — all flat 0 in All-Stars).
- **Sonic `screen_x` is camera-inflated:** idle Sonic rolls forward on slopes and the camera scrolls, so even a
  do-nothing policy gains `screen_x`. For Sonic, trust **RINGS + TIME-survived** (camera-independent), not
  `screen_x`. The eval uses idle-baseline subtraction + a scripted-RIGHT ceiling (see `reach_eval.py`), but for
  ad-hoc demos use the HUD counters.

### 1.2 ★ The VLM video-judge FALSE-POSITIVES deaths (the night's key catch)
We added a RAM-free check: a local VLM (Gemma-4-12B) watches sampled rollout frames and judges progress/death
(`planner_poc/vlm_video_judge.py`). It is genuinely useful (it correctly caught base-model idling/death), BUT:
- **It calls "died" when a hazard is merely NEAR the sprite.** On `kl__state7` the judge reported "Mario dies to
  a fireball ~70 s." Direct HUD audit refuted it: the in-game **TIME counter counts down monotonically
  300→255→221→…→169 with NO reset** and lives steady at 9. In SMW a death **reloads the level and resets TIME**,
  so a continuous countdown PROVES no death. **Mario survived the full 90 s; RAM `died=False` was right; the VLM
  was wrong.**
- **Lesson (now a stored memory):** NEITHER RAM NOR THE VLM IS RELIABLE ALONE, and they err in OPPOSITE
  directions (RAM under-reports deaths + inflates magnitude; the VLM over-reports deaths). The reliable arbiter
  is a **game-intrinsic HUD counter read from the pixels** — SMW/SMB **TIME** (resets on death) or **lives**,
  Sonic **RINGS + TIME** — cross-checked against both. **NEXT: add a tiny HUD-OCR death/again detector to the
  judge pipeline** so "died" is decided by the timer reset, not the VLM's gestalt.
- **Gemma judge position bias:** in A/B compare it has an "always pick RUN A" bias on ambiguous pairs. We caught
  it only by running BOTH orderings (A/B and B/A) and discarding pairs that flip. Always order-control compares.

### 1.3 Degenerate / contaminated start states
- **SMW demo start-state index ≠ obvious level position.** `demo_start_states` are sorted by demo-dir timestamp;
  state 0 is a hard/death-prone spot, not the clean 1-1 start.
- **SMW state 2 is a "COURSE CLEAR!" results screen** (Mario on a black bonus screen), which makes every model
  score a bogus 10/10. Visually verified and excluded. Audit start states before trusting their scores.
- **"survived 90 s" ≠ skill:** a model that idles against a wall never dies and scores "survived" (SMW
  `situ_state5`). Always pair survival with advance.

### 1.4 Emulator / env gotchas (carried from AGENTS.md, still true)
- **mGBA renders blank until stepped** — a frame grab BEFORE the first step looks black (false BLANK in
  env_healthcheck). The furthest_rollout guards this (`if frame.mean()<1: step once`).
- **Genesis has no in-process backend** (Mednafen subprocess only) → no frame-exact save/load for `.md`. SNES/GB
  /GBA emulator envs are in-process with save/load.
- **stable-retro N64** needs a source rebuild (`CMAKE_ARGS="-DENABLE_HW_RENDER=ON -DBUILD_N64=ON"` + angrylion
  sw renderer; warm up ~5 frames before the first `get_screen`).
- **State export is DE-FORKED**: TheXTech reads `/proc/<pid>/mem` (stock RelWithDebInfo build, non-PIE → fixed
  addresses); Solarus auto-overlays the Lua state-export at boot. No source/quest fork needed.
- **YouTube n-challenge:** bare yt-dlp returns only storyboards; working recipe is
  `python -m yt_dlp --cookies cookies.txt --js-runtimes deno:.../deno --remote-components ejs:npm`
  (deno NOT on PATH). `yt_farm.py` wires it. `cookies.txt` is gitignored — never commit.

### 1.5 GPU / process hygiene
- 4× RTX A6000 (~46 GB free each), 128 CPU cores. Two grinders ran on GPU 0–1 (SMW) and 2–3 (cross-game) in
  parallel; ~2 rollouts/GPU max (each loads a ~600 M policy + Qwen-2B). Don't oversubscribe.
- **Kill by NUMERIC PID only** (no pkill/killall — repo rule). The record server traps SIGTERM; `kill -9`
  orphans the child game+Xvfb.
- Always verify GPUs are at ~1 MiB before/after a run (`nvidia-smi --query-gpu=memory.used --format=csv`).

### 1.6 venv / repo
- Use the uv `.venv` and ISOLATE from any outer virtualenv:
  `env -u VIRTUAL_ENV -u PYTHONPATH PYTHONPATH=<repo>:<repo>/planner_poc`. Repo path overridable via
  `NITROGEN_REPO`. Install with `uv pip install <x> --python .venv/bin/python`.

## 2. WHAT WE LEARNED (this session, beyond the recipe)

1. **Demo-fit is the working plan-OOD recipe** and it GENERALIZES + POOLS + MERGES into one model (see
   `docs/research/DISCRIMINATOR_RESULTS.md`): SMW/MMX/SMB1 all widen Δ_plan from ONE pooled plan-head fit;
   plan_head (plan-OOD) + Sonic LoRA (actor-OOD) merge with no interference; null-invariance exact.
2. **The ducking collapse is a DATA artifact** (one constant terse plan → plain BC drops rare actions). Two
   fixes: KL-anchor (winner, preserves the whole action space by construction) and situational labels (2nd,
   taxonomy treadmill). See `docs/research/ARCH_WARROOM.md` R9.
3. **Staleness is TEXT-bound, not token-bound** (R11): the K plan tokens are remarkably stable (tok-drift
   ~0.001); re-grounding tokens (forward-pass TTA) doesn't help; LIVE re-planning can HURT (MMX −11). The lever
   is plan TEXT quality, not token-TTA or actor-weight-TTT.
4. **Evocation vs Addition dichotomy** (R11/R13): the VLM can EVOKE a primitive the DiT already owns (duck
   1.2%→10.8% on command) for free, but precise OUTCOMES the DiT lacks (spin-jump-KILL Rex: jump 7.2× evocable
   but kill-outcome flat) are ADDITIONS that must be LEARNED. Route by emulator OUTCOME, not button proxy.
5. **Honest demo verdict:** trained models are MODESTLY/selectively better than base — they go further (MMX 3×,
   Sonic ~10× by rings, SMW kl 4×) but the far runs often DIE; no model beats a level. The standout demos are
   the ones that are BOTH furthest AND survive (Sonic `pooled_state0`: 40 rings + survives 90 s vs base 4 rings
   + death at 29 s; SMW `kl_state7`: survives a lava fortress where base dies at 13.6 s). Consistent with the
   standing conclusion that real long-horizon capability needs environments/RL.

## 3. NEXT STEPS (what we're thinking)

### 3.1 ★ Persistent "learning tokens" (owner's proposed architecture — the headline next direction)
Instead of (R13/Opus) modulating the single always-on `_GAME_ID_TOKEN` to hold a consolidated skill, the owner
proposes a **dedicated bank of N (32/64/128) persistent "learning tokens" per game** — always present, modulated
to represent the capabilities LEARNED for that game. This is the better long-term form (more capacity for a
skill LIBRARY; cleaner concept) and is the SAME family as the game-channel idea, just wider. Design (see the
full discussion in this session's transcript + `docs/research/FORWARD_S2_TO_S1.md` §3):
- **Separation:** plan tokens = transient intent (this moment, from text); **learning tokens = persistent
  capability** (what this game taught the actor). Directly attacks the token-dilution wall — S2 stops naming
  primitives in prose because they live in the persistent bank.
- **Wiring:** a new `_LEARN_TOKEN` type + a per-game embedding bank (`nn.Embedding(games×N, dim)`), placed in
  the VL sequence like the K plan tokens (`nitrogen.py:481-495`) but **NOT added to `apply_null_mask`** so they
  persist under null. Zero-init + a padding/zero learning-id (like `game_id=0` = unconditional) so an un-learned
  game stays **base-exact by construction** and the change is identity at init.
- **Null-invariance semantics (the crux, unchanged from R13):** you now have 3 levels — (1) hard base, (2)
  null-with-learnings = the game's instinctual policy, (3) plan = instinct + intent. The plan-CFG contrast
  (3 vs 2) stays **bit-exact maskable** (plan tokens still mask cleanly on top of the persistent learnings);
  what you relax is the CFG reference (null moves base→base+instincts), which IS the definition of instinct.
- **It's per-game prefix-tuning / soft-prompts** in the DiT cross-attention KV (Li & Liang 2021; P-tuning). The
  novelty is the WRITE op (emulator-verified consolidation) + the masked-null-preserving construction.
- **Risks:** 32–128 always-on KV tokens add attention compute every DiT step and are free params that can
  overfit small demo data → start at **32**, guard with the expressiveness battery (R≥0.80) + null bit-identity.
  Static per-game vectors suffice (the DiT's own cross-attention gates them state-dependently — a "duck" vector
  fires only near bullets); frame-conditioning likely unnecessary.
- **TODO:** spec `_LEARN_TOKEN` + 32-slot per-game bank wired parallel to the plan path (persistent, zero-init,
  base-exact at init); make `demo_bc.py --consolidate` write a skill into it.

### 3.2 The minimal recursion experiment: CONSOLIDATE-DUCK (both war-room agents, unanimous)
The first turn of "discovery → instinct → higher abstraction": evoke duck (P1) → verify the bullet-state with a
save-state (`maneuver_router.py`) → **KL-anchored self-distil** the plan-conditioned duck into the persistent
channel (game-id row OR the new learning-token bank) so the **null policy ducks at bullet-states WITHOUT the
plan token** → then re-run the live-plan probe with a plan that OMITS duck and show it still survives (= S2
stopped naming it, bandwidth freed). New flag `demo_bc.py --consolidate <channel>` (~30 lines, reuses KL-anchor
+ duck_probe). 3 seeds; pass bars in `docs/research/FORWARD_S2_TO_S1.md` §4. NOT Rex (near-chance, needs a
sprite-status kill detector first).

### 3.3 RL on the emulator save-state substrate
Actor = plan-head (+ optionally DiT-LoRA / learning tokens). Either a critic (long credit path) or **save-state
GRPO** (sample K plans from a save-state, rank by emulator outcome, no critic net). Reward MUST be
survival-weighted (raw `screen_x` RWBC = suicide-sprint exploit; see DISCRIMINATOR_RESULTS). Owner mentioned
verl / prime-rl. Needs the sprite-status / level-complete detectors for dense checkable reward.

### 3.4 Smaller, verified follow-ups
- **HUD-OCR death detector** in `vlm_video_judge.py` (§1.2) — decide "died" by the TIME-reset, not the VLM.
- **Sprite-status RAM** for SMW kills → unblocks the Rex addition path + true kill-reward.
- **SMW 1-1 level-complete detector** (a `p-levelcomplete` todo got partway) → the "did we beat the level"
  signal the owner asked for.
- **Stabilize plans:** `--replan-every N` + hysteresis (the ~50-60% plan flip-rate is in the TEXT, not the

- **Widen K** (8→32) is a LATER bounded-capacity ablation; R9 showed K=8 is NOT the duck bottleneck (data was).
